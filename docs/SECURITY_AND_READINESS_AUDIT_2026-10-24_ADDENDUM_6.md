## 1. Live-query audit — defects found and fixed

Two demonstrable defects were found while auditing `scripts/check-db-acl.mjs` and fixed locally:

1. **`search_path` extraction/evaluation was too loose.** The query previously returned the raw `proconfig` setting (`search_path=public`), and the evaluator only required the substring `public`. That accepted unsafe multi-schema paths such as `attacker, public`.
   - Fix: SQL now returns just the value via `split_part(setting, '=', 2)`.
   - Fix: the evaluator requires the trimmed `search_path` to be exactly `public`; empty → `SEARCH_PATH_MISSING`, otherwise → `SEARCH_PATH_UNSAFE`.
2. **A catalog row with an omitted privilege column could pass as safe.** If a row lacked `public_execute`/`anon_execute`/`authenticated_execute`/`security_definer`/`service_role_execute`, the falsy `undefined` would not trip the unsafe-grant checks.
   - Fix: the evaluator now fails with `INCOMPLETE_ACL_ROW` when any required boolean field is not a boolean.

Effective `EXECUTE` calculation (implicit `PUBLIC` via `has_function_privilege('public', ...)`, `anon`/`authenticated`/`service_role` via the same) was reviewed and is correct. Read-only transaction, `statement_timeout`, `connectionTimeoutMillis`, and `client.end()` cleanup in `finally` are present for both success and failure. No URL, credential, or query result is logged or persisted.
